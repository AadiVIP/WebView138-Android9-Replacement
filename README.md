# WebView138-Android9-Replacement

Replace the legacy WebView provider (Chrome 81, `com.android.webview`) of an **Android 9 (API 28)
ARM64 guest** with **Google WebView 138.0.7204.179 (arm64-v8a universal)**, systemlessly, via a
Magisk module that delivers a static resource overlay (RRO). No signed partition file is modified,
re-signed or deleted — which is exactly why rollback is a module removal plus a reboot.

> **Status, stated plainly.** The overlay and module are **built, independently audited,
> deterministically rebuildable, and sandbox-tested end to end** (409 checks across six suites,
> 0 failures — see [QA below](#quality-assurance-evidence)). **No claim is made that the module
> has been flashed or that WebView 138 has rendered a page on the target guest.** The runtime
> acceptance tests are in `docs/INSTALLATION_GUIDE.md` §7, to be run by the operator after an
> approved install. Every document in this repository labels each fact as `MEASURED`,
> `SOURCE` (quoted from AOSP `android-9.0.0_r35`), or `UNTESTED`.

## How it works (30-second version)

On Android 9 the WebView provider list **is** the resource `android:xml/config_webview_packages`
inside the signed `framework-res.apk`. This project does not touch that file. Instead a 2.7 KB
**static RRO** — `targetPackage="android"`, `isStatic="true"`, unsigned by design — replaces that
one resource from `/vendor/overlay`, a directory Android 9 scans with `SCAN_AS_SYSTEM`, where no
platform signature is required (verified from source and from shipping `/vendor/overlay` contents
on an Android 9 device). The overlay lists:

1. `com.google.android.webview` — first, `availableByDefault="true"`, `isFallback="false"`, with
   the real 959-byte Google certificate as `<signature>` element text (1280-char single-line
   base64). Declaring the signature is what lets a normal `/data` `pm install` pass the platform's
   signature gate — no system-app flag, no platform key.
2. `com.android.webview` (the factory WebView 81) — preserved verbatim, so the guest is never left
   without a working WebView, and rollback is automatic.

A **Magisk module** carries that overlay into `/vendor/overlay` via magic mount during
`post-fs-data` — before `system_server`/`PackageManagerService` scans — which is the only way a
read-only `/vendor` accepts a new file. `customize.sh` refuses a bad install (wrong API, tampered
bytes, missing scan dir); `service.sh` logs boot-time verification and fixes one stale
`webview_provider` pin (backed up first); `uninstall.sh` restores what it changed. WebView 81 is
never modified, disabled or removed by anything in this project.

Full mechanism, with every source citation: `docs/ARCHITECTURE.md` and
`docs/reports/INTEGRATION_PLAN.md`.

## Quick start (operator)

```sh
# on the guest, all commands via su; MiXplorer is used to stage the four files
# 1. probe (read-only) — must report Magisk PRESENT and API 28
sh /sdcard/Download/guest_probe.sh 2>&1 | tee /sdcard/Download/probe.txt
# 2. module (drop-in route, the tested one)
unzip -o WebView138-Replacement-Magisk.zip -d mod
su -c 'sh /sdcard/Download/magisk_deploy.sh --check  --src /sdcard/Download/mod/webview138-replacement'
su -c 'sh /sdcard/Download/magisk_deploy.sh --install --src /sdcard/Download/mod/webview138-replacement --i-reviewed'
# 3. the 138 package (obtain per tools/download_webview_apk.sh, then:)
su -c 'pm install -r /sdcard/Download/webview138.apk'
# 4. reboot, then verify (do not assume)
su -c 'dumpsys webviewupdate | head -25'   # expect (com.google.android.webview, 138.0.7204.179)
su -c 'cat /data/adb/modules/webview138-replacement/boot-verify.log'
```

Then do not call it a success until the seven runtime checks in
`docs/INSTALLATION_GUIDE.md` §7 pass. Rollback: `docs/ROLLBACK_GUIDE.md`
(short version: `magisk_deploy.sh --remove --i-reviewed`, reboot, done).

## Rebuild from source

The build machine that produced the release artifacts was a Termux shell on the same Android 9
arm64 host as the target environment (no aapt, no Java, no openssl). The chain, with explicit
flags so it also runs from a plain checkout of this repository:

```sh
# 1. overlay (pure-Python AXML + resources.arsc writer; template = aapt2 RRO manifest donor)
python3 tools/build_overlay.py \
    --out output/webview138-provider-overlay.apk \
    --cert src/inputs/V2_cert.der \
    --base-xml src/inputs/guest_config_webview_packages.axml \
    --template src/inputs/FrameworksResCommon.apk
# 2. independent audit; writes the delivery manifest ONLY if every check passed
python3 tools/verify_overlay.py output/webview138-provider-overlay.apk \
    --cert src/inputs/V2_cert.der \
    --package com.qoder.webviewprovider.overlay \
    --base-xml src/inputs/guest_config_webview_packages.axml \
    --write-manifest output/webview138-provider-overlay.manifest
#    (add --apk <the 222 MB package> to also prove the overlay cert == the package signer)
# 3. module (refuses to run without the audit manifest; copies the audited bytes byte-for-byte)
python3 tools/build_magisk.py \
    --overlay output/webview138-provider-overlay.apk \
    --manifest output/webview138-provider-overlay.manifest \
    --webview-apk <path to the 222 MB package, or omit> \
    --stagedir work/magisk_stage --zip output/WebView138-Replacement-Magisk.zip
# 4. independent re-read of the finished ZIP + sandboxed lifecycle of every script
python3 tools/audit_magisk.py --webview-apk <path or omit>
python3 tools/selftest_magisk.py --report work/magisk_selftest.txt
```

The build is **deterministic**: the overlay, the manifest and the module ZIP were rebuilt from
these inputs and compared **byte-for-byte** against the shipped artifacts (`cmp` identical;
ZIP sha256 `b6323730…` reproduced twice in a row).

## The Google WebView package — not released with this project

The tested replacement package is:

| Property | Value |
|---|---|
| package | `com.google.android.webview` |
| versionName / versionCode | `138.0.7204.179` / `720417901` |
| `minSdkVersion` / `maxSdkVersion` / `targetSdkVersion` | 26 / **28** / 35 (the `maxSdk=28` makes it the Android 8–9 branch build) |
| ABIs | `arm64-v8a` + `armeabi-v7a` (universal); the arm64 `libwebviewchromium.so` is `ELF64/EM_AARCH64` |
| size / SHA-256 | 222218902 B / `39f8eee7b6a4588c55e9299f95bfdff0c0943414bf468241becd0ed588e444a0` |
| signer | Google, `O=Google Inc., OU=Android, CN=webview`, RSA-2048; cert SHA-256 `6faf3c41…ba6fe5` (== the cert the overlay declares) |

**Licensing: Android System WebView is proprietary Google software** (signed by Google, no license
text bundled in the APK, distributed under Google's terms via the Play Store). It is therefore
**not redistributed** in this repository or as a release asset. `tools/download_webview_apk.sh`
is the sanctioned path: it tells you where to obtain the exact build from official/authorized
channels (Play Store on the device is the canonical source; a mirror copy is acceptable only if
it verifies) and then **refuses to proceed unless the file's SHA-256 equals the tested value and
its manifest identity matches**. It explicitly rejects the ARMv7-only `138.0.7204.181` build —
that file cannot work on this ARM64-only guest.

**The guest is 64-bit-only** (measured from the ROM package's `manifest.json`:
`"support_a32": false`, `"support_a64": true`, `"minimum_sdk_int": 28`), so the `arm64-v8a`
library is the one that loads.

## What is verified, and what is not

Verified (build machine, evidence in `docs/reports/VALIDATION_REPORT.md`): file formats, the
provider grammar rules, the certificate chain (v2 signature cryptographically valid, self-signature
valid, cert == overlay's `<signature>` text == both APKs' embedded signer), the four Android 9
provider validity gates against the measured APK values (source-level), module structure, script
safety (destructive-command scan), sandboxed module lifecycle, deterministic build.

**Not verified (read before installing):** runtime behaviour on the guest — Magisk presence/version
(user-reported v30; probe it), the `update-binary` ↔ Magisk ABI (re-implementation; the drop-in
route is the tested path), magic-mount of a *new* overlay directory, `idmap` success, and the
native 64-bit library load. The exact unverified list and the commands that settle each item are
in `docs/ARCHITECTURE.md` §8 and `docs/INSTALLATION_GUIDE.md`.
